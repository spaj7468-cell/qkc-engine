A quiz engine
with no dependencies
and no surprises.

QKC Engine assembles, serves and scores knowledge-check tests from strictly partitioned question banks (grade → subject → term → topic). One plain JavaScript file, UMD + ESM, no build step, no runtime deps — the same core that runs the QKC trainer with its 42 823 questions.

v1.0.0 0 dependencies UMD + ESM ≈2.2 KB gzip seeded & reproducible MIT
01 · install

Three ways in, zero lock-in.

The package is published straight from this repository: npm from git, any git CDN, or a plain <script> tag. Pick whichever fits your stack.

# npm / pnpm / yarn — straight from git npm install github:spaj7468-cell/qkc-engine // then, CommonJS const QKC = require('qkc-engine'); // or ESM / bundlers import QKC from 'qkc-engine';
<!-- classic script: window.QKC --> <script src="https://cdn.jsdelivr.net/gh/spaj7468-cell/qkc-engine@main/dist/qkc-engine.js"></script> <!-- or as an ES module --> <script type="module"> import QKC from 'https://cdn.jsdelivr.net/gh/spaj7468-cell/qkc-engine@main/dist/qkc-engine.mjs'; </script>
// quickstart — build and score a test in six lines const eng = QKC.engine(bank); // bank: { grade: { subject: { quarter: [items] } } } const test = eng.build({ grade: 5, subject: 'math', quarter: 1, count: 10, seed: 'demo' }); const safe = test.items.map(({ c, ...i }) => i); // strip answers before sending to a client const res = eng.score(test, answers); // answers: { [itemId]: value } console.log(res.pct, res.perTopic); // 87 { equations: { correct: 3, total: 4 }, … }
02 · api

Small surface, documented behaviour.

Everything is pure and synchronous: same seed → same test, every time. No DOM, no network, no globals beyond the single QKC export.

QKC.engine(bank)

Creates an engine instance over a bank container. The bank is never mutated.

engine(bank: Bank): Engine

engine.build(opts)

Draws a deduplicated test from a filter: grade, subject, quarter (or 'all'), topics, count, seed (string or number).

build({ grade?, subject?, quarter?, topics?, count?, seed? }): Test

engine.score(test, answers)

Compares trimmed, case- and comma-insensitive values. Returns counts, percent and per-topic accuracy.

score(test: Test, answers: { [id]: string }): Result

engine.validate()

Structural audit of the whole bank: missing text/answer, choice options without the correct one, bad bool values…

validate(): { ok: boolean, errors: string[] }

engine.count(f) / engine.topics(f)

Introspection over the same filter object: how many items match, and which topics they fall into.

count(f?): number topics(f?): { topic, count }[]

QKC.rng(seed) / QKC.items(bank, f)

The seeded mulberry32 PRNG and the raw filtered item list, exported for your own pipelines.

rng(seed): { next, int, pick } items(bank, f?): Item[]
03 · bank schema

Banks are plain JSON-shaped objects.

Partitioning is structural: an item lives at exactly one grade → subject → quarter path, so a term can never leak into another term's test. Topics slice inside a term.

fieldtypemeaning
tstringquestion text
ty'choice' | 'bool' | 'input'answer type: pick an option, true/false, or free keyboard input
cstringcorrect answer (kept server-side; strip before clients see it)
ostring[]options, required for choice; shuffled deterministically per seed
estringexplanation shown after answering
tpstringtopic inside the term (for filters and per-topic stats)
qnumberterm index (1–4, or 1–3 for trimester calendars)
{ "5": { // grade "math": { // subject "1": [ // quarter / trimester { "t": "x + 7 = 41. x = ?", "ty": "input", "c": "34", "e": "x = 41 − 7 = 34.", "tp": "equations", "q": 1 }, { "t": "LCM(8, 6) = ?", "ty": "choice", "c": "24", "e": "LCM(8,6) = 24.", "tp": "divisibility", "q": 1, "o": ["6", "8", "24", "48"] } ] } } }
